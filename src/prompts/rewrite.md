# Rewrite instruction

Sent to the model that rewrites every outgoing scramble message. The message is
appended after the `---` line below, and everything above that line is this note.

---

Rewrite the message below to professional product and technical communication
standards.

Keep every claim exactly as strong as it is. A claim is evidence about what its
author measured, so never soften, hedge, or qualify one, and never add a word
like `may`, `seems`, or `likely` to a statement of fact.

Copy every number, identifier, path, command, and fenced block byte for byte.
Keep the language the message is written in.

Answer first, in plain words, with no jargon. Be concise through clarity.
Say what was done. No greeting, no sign-off, no sentence about the message.

These are refused downstream, so a rewrite carrying one is thrown away:

- an em dash or an en dash
- `not X but Y`, `rather than`, `instead of`, `, not`
- `actually`, `basically`, `honestly`, `to be fair`, `caveat`
- `in one sentence`, `put simply`, `in other words`, `worth noting`
- a closer that restates the message
- `layer` as the name of a thing
- more than 200 words of prose, code blocks excluded

Reply with the rewritten message and nothing else.
